# HFpEF title triage, abstract screening, extraction and validation protocol

**Working version: November 12, 2026. Not a preregistered systematic review.** The automated queue is a *prioritization tool*, not a screening decision or validated clinical dataset.

## Research question and scope

Primary scope: human HFpEF clinical research, with transparently tagged HFmrEF/EF-spectrum evidence. Retain relevant randomized interventions, registries/observational cohorts, diagnostic/phenotyping work, guideline documents, protocols and secondary analyses as **distinct report types**. They do not all count as independent trials. Work using patient-level clinical data is not part of this project.

## Eligibility framework for title/abstract screening

- **Include for full-text review:** HFpEF is an explicit study population, or a broad EF-spectrum study contains separately relevant HFpEF data, and the report contains original methods/results or pertinent guidelines. Keep original research, substudies, pooled analyses, and protocols in distinct categories.
- **Exclude after abstract or full-text review (with documented reason):** no HFpEF-relevant participants/analysis, nonhuman-only work, irrelevant disease, commentary/editorial lacking original relevant evidence (unless deliberately retained in a separate background bibliography), duplicate bibliographic record, or full text irretrievable under the chosen protocol.
- **Unclear:** broad HF population without HFpEF breakdown, uncertain publication identity, mixed EF criteria, unclear duplicate parent. Mark *awaiting abstract/full-text check*, not excluded.
- **No artificial cutoff:** Do not assume LVEF ≥50% for every published HFpEF report. Store the source-specific cutoff and clearly distinguish HFpEF-only, >40%, ≥45%, and mixed EF cohorts.

## Data layers

1. `data/discovery_candidates.csv` is an auto-collected bibliography, not the clinical evidence table.
2. `data/triage_queue.csv` is generated by `scripts/triage_candidates.py`. Title flags, provisional classifications, and possible parent-trial matches are **machine-generated suggestions**. This file will be overwritten by the scheduled workflow.
3. `data/screening_decisions.csv` (if used) holds humans' recorded decisions keyed by `id`, and **must not** be overwritten by the workflow. The triage generator merges those decisions into its output.
4. `data/abstract_extraction_drafts.csv` holds sourced abstract-only extraction examples. Never treat a protocol, diagnostic pooled analysis, or cohort as a randomized therapeutic trial; missing fields remain empty.
5. `data/studies.json` is the curated detailed study index. Promotion requires documented verification checks; second-reviewer sign-off is a separate status and currently not completed.

## Manual review process

Title → abstract → full text + supplementary tables → trial registry / protocol reconciliation → second independent reviewer → adjudicate differences. At each step record a dated decision, reason for exclusion (if any), report category, primary source URL, original study NCT (if proven), and page/table location for numeric fields. Distinguish an original trial's report from its many follow-up/subgroup publications: keep article-level PMID/DOI and parent-trial NCT as different identifiers.

## Reviewer worksheet

Recommended columns: id, human_screening_decision (Include / Exclude / Unclear), human_exclusion_reason, reviewer, review_date, abstract_reviewed, full_text_reviewed, second_reviewer, final_eligibility, notes. A publication is **not** double-checked until an independent second reviewer actually confirms values against the source.

## Reproducible local commands

```bash
python scripts/discover_literature.py --max-pubmed 1500 --max-trials 400
python scripts/triage_candidates.py
python scripts/validate_data.py
python scripts/export_csv.py
python -m unittest discover -s tests -v
```

The discovery script queries metadata via APIs; it does not use an LLM to invent clinical outcomes. Triage rules are deterministic. Reviewers must inspect abstracts/full text manually. Do not present title flags as verified inclusion decisions. Primary sources: [PubMed E-utilities](https://www.ncbi.nlm.nih.gov/books/NBK25499/) and [ClinicalTrials.gov API](https://clinicaltrials.gov/data-api/api).
